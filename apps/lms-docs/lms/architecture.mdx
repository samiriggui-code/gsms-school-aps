# Architecture cible du monorepo LMS

## Choix structurant

Le choix retenu est un monorepo **single-tenant** avec demos LMS/CRM/Landing adaptees:

- `lms-app` est le produit LMS (apprenant + formateur).
- `lms-crm` est le back-office ecole (admissions, dossiers, operations).
- `lms-landing` est le site public (acquisition, SEO, conversion).
- `docs-lms` est la documentation interne equipe.

Ce choix simplifie fortement la mise en production en evitant la dette GSMS multi-tenant.

## Cartographie applicative

### `apps/lms-landing`

Rôle: acquisition et conversion.

Fonctionnalités cibles:

- pages filières / programmes / tarifs,
- demande d'information et pré-inscription,
- checkout de modules complémentaires,
- redirection fluide vers l'espace LMS.

### `apps/lms-app`

Rôle: expérience pédagogique.

Domaines prioritaires:

- `catalog`: formations, parcours, modules, leçons,
- `learning`: progression, contenu, ressources,
- `tutoring`: rendez-vous, suivi, feedback,
- `planning`: cohortes, sessions, calendrier,
- `assessment`: quiz, examens, résultats, certificats,
- `billing-student`: abonnements et achats additionnels.

### `apps/lms-crm`

Rôle: pilotage opérationnel et administratif.

Domaines prioritaires:

- `admissions`: pipeline candidat, pièces, validation,
- `operations`: gestion sessions, salles virtuelles, affectations formateurs,
- `finance`: encaissements, facturation, relances,
- `quality`: conformité, audits, indicateurs de performance.

### `apps/docs-lms`

Role: documentation technique et runbook interne.

- centralise l'etat d'avancement,
- conserve les decisions techniques actees,
- sert de reference d'onboarding.

## Packages partagés

- `packages/database`: schema Prisma unique, seed, generation client.
- `packages/auth`: logique NextAuth partagee entre app et crm.

## Évolutions technologiques recommandées

1. Finaliser redirections et acces par role entre app/crm/docs.
2. Ajouter hardening securite (rate-limit, audit logs, lockscreen reel).
3. Stabiliser conventions techniques (scripts root, checks qualite).
4. Industrialiser la documentation operationnelle.

## Feuille de route suggérée

### Phase 1

- Stabilisation monorepo et scripts partages.
- Mapping role -> acces app.
- Tests de parcours login/redirection.

### Phase 2

- Durcissement securite auth.
- Workflow landing signup special.
- Documentation exploitation/runbook.

### Phase 3

- Optimisation perf et fiabilite.
- Industrialisation qualite (lint/typecheck/tests e2e).
